# K-학당 개인정보·데이터 안전 초안

작성일: 2026-05-26

이 문서는 현재 코드 기준으로 K-학당의 개인정보 처리, 데이터 안전, Google Play 제출 준비 항목을 정리한 초안이다. 법률 자문 문서가 아니라 출시 준비용 운영 초안이며, 실제 출시 전에는 최종 문구와 SDK 구성에 맞춰 다시 검토해야 한다.

## 현재 출시 기본값 요약

- `VITE_ENABLE_CLAUDE_FEATURES=false`를 기본값으로 유지한다.
- 기본 출시 빌드에서는 AI 문제 생성, 사진 기반 AI 캐릭터 변환을 사용자 기능으로 노출하지 않는다.
- 광고 SDK, 결제 SDK, 분석 SDK를 붙이기 전까지는 외부 전송 데이터가 없는 보수 기준으로 문서를 유지한다.
- 정식 출시 전 마지막 점검에서 운영 문의 연락처와 실제 SDK 목록을 개인정보처리방침에 반영한다.

## 1. 현재 앱 동작 기준

- 계정 생성, 회원가입, 서버 로그인 기능은 없다.
- 학습 진행 상태, 출석, 미션, 오답 노트, 캐릭터 설정 등은 브라우저 `localStorage`에 저장된다.
- 사진 아바타를 사용하는 경우 사용자가 직접 고른 사진 또는 촬영 사진이 기기 내 저장 상태에 포함될 수 있다.
- 내부 테스트에서 AI 기능을 켠 환경에서는 Claude API를 브라우저에서 직접 호출한다.
- 광고 SDK, 결제 SDK, 분석 SDK는 현재 코드 기준으로 아직 연동되지 않았다.

## 2. 현재 저장·전송 데이터 정리

### 기기 내부에 저장되는 데이터

- 학습 진행 데이터
  - 이름, 레벨, XP, 코인, 하트, 연속 학습 기록, 일일 미션, 업적, 오답 문제, 학습 일자, 카테고리 통계
- 캐릭터 데이터
  - SVG 캐릭터 설정값
  - 사진 모드 사용 시 사진 데이터(base64)와 사진용 모자/소품 설정
- AI 학습 데이터
  - AI 생성 문제 뱅크와 생성 날짜 메타데이터
- 기타
  - 슬라이딩 퍼즐 튜토리얼 확인 여부

### 외부로 전송될 수 있는 데이터

- AI 문제 생성 사용 시
  - 프롬프트 내용, 문제 생성 요청 정보
- 사진 기반 캐릭터 변환 사용 시
  - 사용자가 고른 사진 데이터
  - 사진 분석 프롬프트

## 3. Google Play 데이터 안전 초안

현재 코드 상태 그대로 출시하면 아래 항목을 보수적으로 검토해야 한다.

### 현재 명확히 말할 수 있는 항목

- 앱 자체 계정 정보 수집: 없음
- 앱 자체 위치 정보 수집: 없음
- 앱 자체 연락처/주소록 수집: 없음
- 앱 자체 결제 정보 수집: 없음
- 앱 자체 광고 SDK 데이터 수집: 아직 없음
- 앱 자체 분석 SDK 데이터 수집: 아직 없음

### 주의가 필요한 항목

- 사진 및 동영상
  - 사진 기반 캐릭터 변환 기능을 출시 빌드에 포함하면, 사용자가 선택한 사진이 외부 AI 서비스로 전송될 수 있다.
  - 이 경우 Google Play 데이터 안전과 개인정보처리방침에서 사진 전송 목적, 보관 여부, 제3자 처리 여부를 명시해야 한다.
- 사용자 제공 콘텐츠
  - 이름 입력, 사진 업로드, 자유 입력 프롬프트가 있다면 사용자 제공 콘텐츠 범주 검토가 필요하다.
- 앱 활동
  - 현재 학습 기록은 로컬 저장만 하고 외부 전송하지 않지만, 향후 분석 SDK를 붙이면 선언 항목이 바뀐다.

## 4. 어린이·가족 대상 관점의 판단

현재 제품 성격상 어린이 또는 가족 대상 가능성이 높다. 따라서 아래 원칙을 출시 기본값으로 둔다.

- 맞춤형 광고는 기본적으로 피한다.
- 광고를 붙이더라도 보상형 광고만 제한적으로 검토한다.
- 상업적 유도 문구는 학습 흐름을 방해하지 않게 최소화한다.
- 결제 유도는 보호자 관점에서도 과하지 않게 설계한다.
- 사진 업로드와 외부 AI 전송은 명시적 안내와 동의 없이 기본 흐름에 두지 않는다.

## 5. 현재 가장 큰 정책 리스크

### 브라우저에서 Claude API를 직접 호출하는 구조

- `src/services/claudeApi.ts`
- `src/services/avatarAiService.ts`

현재 구조는 `dangerouslyAllowBrowser: true` 설정으로 브라우저에서 직접 AI API를 호출한다. 출시 관점에서는 아래 이유로 기본 비활성화 또는 구조 변경이 필요하다.

- API 키 노출 위험
- 사진 데이터의 제3자 전송 고지 필요
- 어린이 대상 앱에서 외부 AI 처리 경로 설명 부담 증가
- 데이터 안전 항목과 개인정보처리방침 복잡도 증가

## 6. 출시 전 권장 결정

### 권장안 A

초기 Google Play 출시에서는 AI 기능을 기본 비활성화한다.

- 운영 플래그 `VITE_ENABLE_CLAUDE_FEATURES=false`를 기본값으로 유지
- 사진 기반 AI 캐릭터 변환 비활성화
- AI 문제 생성 비활성화 또는 내부 테스트 전용 유지
- 스토어 문구와 데이터 안전 항목을 단순화

### 권장안 B

AI 기능을 유지하려면 아래를 먼저 완료한다.

- 서버 경유 구조 또는 안전한 프록시 구조로 전환
- 사진 전송 전 명시적 안내 문구 추가
- 개인정보처리방침에 제3자 처리 항목 추가
- 데이터 보관 기간과 삭제 방침 문서화
- 어린이/가족 대상 여부와 Families 정책 적합성 재검토

현재 단계에서는 권장안 A가 더 안전하다.

## 7. 개인정보처리방침 초안에 반드시 들어갈 항목

- 수집하지 않는 정보: 계정, 연락처, 위치, 결제 정보
- 기기 내 저장 정보: 학습 진행, 캐릭터 설정, 사진 아바타, 오답 노트, AI 문제 캐시
- 선택 기능 설명: 사진 업로드, 카메라 사용, AI 기능 사용 시 외부 전송 가능성
- 제3자 제공 또는 처리: 현재 AI 기능 활성화 시 Anthropic API 처리 가능성
- 데이터 삭제 방법: 앱 삭제 또는 브라우저 저장소 초기화 시 로컬 데이터 삭제
- 아동 사용자 보호 원칙: 맞춤형 광고 미사용, 과도한 결제 유도 지양

## 8. Codex 체크리스트 반영안

- 개인정보처리방침 문서 초안 작성
- 데이터 안전 제출 문안 초안 작성
- AI 기능 출시 기본값 결정
- 광고/결제 SDK 실제 연동 전까지 문서 상태 유지
- 서버 전송 기능 추가 시 이 문서 즉시 갱신
- 정식 출시 전 운영 문의 연락처와 게시 URL 반영 여부 최종 확인
